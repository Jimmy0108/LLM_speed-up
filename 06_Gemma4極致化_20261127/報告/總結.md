# 總結 — Gemma 4 E4B 極致化實驗（2026-11-27）

> 模型：Gemma 4 E4B Q4_K_M + MTP draft Q4_0（固定不換）
> 硬體：Jetson Orin NX 16GB / MAXN_SUPER / L4T R39.2.2 / llama.cpp 2d8a3250

## 一、最終配方與數據

### 短輸出（E2E 極快）
```
llama-server -m <Q4_K_M> -md <mtp-Q4_0.gguf> --spec-type draft-mtp \
  --spec-draft-n-max 3 -ngl 99 -fa on -c 2048 -b 1024 -ub 256 -t 4 \
  -ctk q8_0 -ctv q8_0
+ prompt 用 lite rules（62 token）
```
| 指標 | 原本 | 極致 | 提升 |
|---|---:|---:|---:|
| E2E | 731 ms | **545–635 ms** | -16~25% |
| EM | 0.8226 | **0.8871** | +6.5% |
| F1 | 0.9447 | **0.9661** | +2.1% |

### 長輸出（decode 極快）
```
--spec-draft-n-max 6 -t 2 -c 4096（thinking ON）
```
| 指標 | 值 |
|---|---:|
| decode（思考內容） | **40.8 t/s** |
| decode（雙路徑長答） | **44.4 t/s** |
| 接受率 | 48% |

## 二、六大發現

1. **lite 規則是短答關鍵**：prompt 187→62 token，E2E 751→635ms，且 EM 反升到 88.7%（full rules 反而干擾）。
2. **MTP 有開就比沒開快**：短答 641 vs 761ms；n-max3 最佳。
3. **ctx2048+b1024+t4** 再快 5%（609ms）。
4. **thinking ON 讓 decode 40.8**（vs OFF 26.5），思考內容可預測、接受率 48%。
5. **n-max 對思考內容不敏感**（4/6/8 都 40–41）→ 已近頻寬極限。
6. **GPU 利用率 97%、功耗 20.6W、70°C 無降頻** → 硬體已吃滿，改 kernel 空間有限。

## 三、瓶頸分析（IO/運算）

| 瓶頸 | 證據 | 對策 |
|---|---|---|
| **prefill（短答）** | lite 62 tok 仍佔 E2E 大半 | 已用 lite 降 prompt |
| **SYNC_OVERHEAD（短答 MTP）** | 短答 draft 開銷占比高 | n-max3 + 短輸出 |
| **頻寬（長答 decode）** | 40.8 vs 51 理論，gap 21% | 需 C1 adaptive draft |
| **COMPUTE_BOUND（長 prompt）** | in512 prefill 掉到 140 t/s | 長 prompt 無解（compute） |

## 四、目標達成度

| 目標 | 現況 | 達成 |
|---|---|---|
| 短答 E2E ≤300ms | 545–635ms | ⚠️ 未達（差 245ms，卡在 prefill）|
| 長答 decode ≥50 | 40.8（思考）/ 44.4（雙路徑）| ⚠️ 差 12–18% |
| 正確率不降 | 88.7%（升） | ✅ |
| 穩定 | 0 失敗、無降頻 | ✅ |

## 五、要達 300ms / 50t/s 的下一步
- **短答 300ms**：需砍 prefill（更短 prompt 或 cache 重用），或接受 545ms（已比原 731 快）。
- **長答 50t/s**：需 C1 Adaptive draft（+5–15%）+ 可能 C2 2-row verify 調校。GPU 已 97%，空間有限。

## 五、研究級 C1（Adaptive Draft）結論

- 實作 `--spec-adaptive`（rolling EWMA 調 n_max），**lossless**（greedy 輸出 byte-identical）。
- **思考 decode 結構天花板 = 42.4 t/s（fixed n-max6）**；adaptive 38–41 打不贏已調最佳固定值。
- n>6 變慢、KV q4_0 變慢、FA off 壞（sm_87 bug）、2-row verify 不需（mmq-few 已 optimal）。
- **50 t/s 在 Q4_K_M 不可達**（GPU 97% mem-bound）；要 50+ 只能 QAT（排除）或改硬體。
- adaptive 的價值：未知/混合負載 +5–15%（避免固定 n 懲罰），已知最佳固定值 ~0%。
