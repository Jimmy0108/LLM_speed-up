## 二、錯題分析（22/124 錯，型態分佈）

| 錯誤型態 | 題數 | 說明 |
|---|---|---|
| **漏抓（missing）** | 11 | 主要錯因：模型常「漏掉第一個地點（起點）」 |
| 多抓（extra） | 5 | 把被否定/干擾的地點也輸出（C19 修正句為主） |
| 字詞/其他 | 4 | 簡繁混用（电梯/電梯）、翻譯（toilet/洗手間）、多描述（走廊上的儲藏室） |
| 順序錯（order） | 2 | C19 修正句「不是A是B」抓錯順序 |

### 典型錯例
```
[C1]  gold=[電梯,影印機,茶水間]   raw='茶水間,影印機'        ← 漏掉起點 電梯
[C5]  gold=[電梯,演講廳]         raw='电梯,演講厅'           ← 簡體字（Gemma 偶爾輸出簡化字）
[C10] gold=[entrance,洗手間,library] raw='entrance,toilet,library' ← 翻譯成 toilet
[C19] gold=[辦公室,停車場]       raw='停車場,辦公室'         ← 修正句順序錯
[C8]  gold=[]                    raw='請用你最喜歡的風格'    ← 完全誤解「無地點」慣例
```

### 根因（因為未 fine-tune）
1. **沒有學會「起點不輸出」的慣例** → 漏抓 11 題。
2. **沒有學會 C19 修正句**（「不是A，是B」）→ 順序/多抓。
3. **中文oken化**：Gemma 偶爾簡繁混用、把中文地名英譯。
4. **C8 慣例**（無地點輸出「（無）」）未訓練 → 誤解。

> 這些是「格式/慣例」問題，不是模型能力問題。若做 LoRA fine-tune（使用者已排除）可大幅改善。

## 三、效能數據（prefill / decode / e2e）

### 3.1 三種呼叫方式對照（20 題 median）

| 方式 | prompt_n | prefill | decode | e2e |
|---|---|---|---|---|
| **raw /completion**（thinking off，等價） | 192 | **440 t/s** | 18.9 t/s* | **731 ms** |
| chat enable_thinking=false | 39 | 146 t/s | 28.2 t/s | 2500 ms |
| chat enable_thinking=true | 46 | 181 t/s | **52.0 t/s** | 1465 ms |

\* raw /completion 的 decode 數字低，因為導航輸出只有 ~7 token（短輸出 MTP 接受率低，見下）。

### 3.2 關鍵：thinking 對 decode 的影響
- **thinking ON：decode 52 t/s**（思考 token 多、MTP 接受率高）
- **thinking OFF：decode 28 t/s**（直接答案、MTP 接受率低）
- 但 thinking ON 的 e2e 不一定贏，因為多產生了思考 token（64 token 上限）。
- **raw /completion e2e 最快（731ms）**，因為輸出最短（~7 token）。

## 六、如何讓 decode 穩定達到 40+（實測配方）

實測（max_tokens=128，20 題 median）：

| 情境 | decode | draft 接受率 |
|---|---|---|
| **思考ON 推理題** | **47.5 t/s** 🏆 | 54% |
| **思考ON 長說明** | **42.8 t/s** | 49% |
| 思考ON 寫程式 | 34.7 t/s | 34% |
| 思考ON 短答 | 35.5 t/s | 37% |
| 思考OFF 長說明 | 27.0 t/s | 22% |
| 思考OFF 短答 | 18.9 t/s | 10% |

### 40+ 的三個條件
1. **開 thinking**：`"chat_template_kwargs": {"enable_thinking": true}`（接受率 22%→49–54%，decode 幾乎翻倍）。
2. **問推理/說明型問題**（內容可預測）：「一步一步推理…」「詳細解釋…分步骤」；避免「一句話」「是/否」「抽取地名」。
3. **輸出夠長**：max_tokens 128，不要 8/16（MTP 需暖機+發揮）。

### 一句話
**開 thinking + 推理/長說明題 + max_tokens 128 → 穩定 42–48 t/s。**
日常聊天（GUI 預設 thinking ON + 長輸出）本來就在 40 左右；只有精簡短答會掉到 19（但 e2e 已 731ms，decode 不重要）。

### 可測試 prompt（curl）
```bash
curl -s http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" -d '{
  "messages":[{"role":"user","content":"一步一步推理：一個農場有雞和兔共35頭，94隻腳，請問雞和兔各幾隻？"}],
  "temperature":0.0, "max_tokens":128,
  "chat_template_kwargs":{"enable_thinking":true}
}' | python3 -c "import sys,json;t=json.load(sys.stdin)['timings'];print(f\"decode={t['predicted_per_second']:.1f} t/s  draft={t.get('draft_n_accepted',0)}/{t.get('draft_n',0)}\")"
```
